The LastPass Disaster: 25 Million Encrypted Vaults Stolen — And Still Being Cracked

December 2022 — Ongoing 7 min read 5 sources
Ongoing — 2022 to Present
In August and December 2022, hackers breached LastPass twice — stealing the complete encrypted vault database for 25M+ users. By 2024, attackers had cracked enough master passwords to steal over $35M in cryptocurrency from LastPass customers. The breach is still ongoing.

What Happened at LastPass

The LastPass breach unfolded in stages, each worse than the last. In August 2022, attackers gained access to LastPass's developer environment through a single compromised developer account. LastPass initially characterized this as limited — source code and technical information, nothing customer-facing.

That assessment turned out to be badly wrong. Using the developer access obtained in August, the attackers pivoted. By September 2022 they had leveraged that foothold to reach a separate cloud storage environment where LastPass kept customer data backups. LastPass did not detect or disclose this second intrusion for months.

In December 2022, LastPass finally confirmed what had actually been stolen: the complete encrypted vault database for every customer, along with billing information, names, email addresses, telephone numbers, and IP address logs. Critically, the website URLs stored in each vault — which tell attackers which services a user has accounts with — were not encrypted. Attackers could immediately identify which stolen vaults were worth targeting.

The stolen vault files are static. Unlike a live login attempt, there is no lockout, no rate limiting, no detection. Attackers can run password-cracking attempts against their local copy of your vault indefinitely, at whatever speed their hardware allows. For accounts with weak master passwords — or accounts where LastPass's default iteration count was low — this made cracking feasible within months.

Why "Encrypted Vaults" Got Cracked

LastPass encrypted customer vaults using PBKDF2-SHA256 — a key derivation function that stretches your master password into an encryption key. The critical variable is the iteration count: how many times the function runs before producing the final key. More iterations means more computation required to test each password guess.

LastPass's default was 5,000 iterations. The current OWASP recommendation for PBKDF2-SHA256 is 600,000 iterations. Accounts created with older versions of LastPass, or accounts that were never migrated to higher settings, had keys derivable at a fraction of the computational cost of a modern standard. On a consumer GPU, testing millions of password guesses per second against a 5,000-iteration vault is entirely feasible.

The problem compounds with metadata. Because LastPass left URLs unencrypted, attackers did not need to crack every vault blindly. They could identify which users held cryptocurrency wallets — high-value targets — and concentrate their cracking resources accordingly. The $35M in documented cryptocurrency theft by 2024 represents only the verified cases from a known victim pool.

There is also a structural problem with any cloud-based service that holds your encrypted data: a single breach exposes everyone's data simultaneously. The attacker does not need to compromise individual users. They compromise the service once, exfiltrate the database, and then work on the stolen copy at their own pace, forever.

LastPass encrypted your vaults, but used weaker parameters than current standards. With stolen vault files, attackers have unlimited time to brute-force your master password offline — with no lockouts, no rate limits, and no detection possible.

The memory-hardness of Argon2id is the key distinction. PBKDF2 can be parallelized across thousands of GPU cores simultaneously — each core independently tests password guesses. Argon2id's 128 MB memory requirement means each parallel attempt requires 128 MB of RAM. A GPU with 8 GB of memory can run fewer than 64 simultaneous attacks. The same hardware that cracks PBKDF2 vaults at millions of attempts per second is bottlenecked to thousands of attempts per second against Argon2id — a difference that turns a feasible attack into an impractical one.

1Cryptor also encrypts file and folder names, not just file contents. Even if your encrypted files were somehow obtained, an attacker would learn nothing about what you're protecting. There is no metadata to prioritize, no directory structure to analyze — only opaque ciphertext.
