ENCRYPTION PIPELINE

From your password
to an encrypted vault.

Every step runs entirely on your device. Nothing sensitive crosses the network unencrypted.

01

Password Input

Argon2id hashes your password with 128 MB memory and 4 iterations. Brute force is infeasible by design.

→
02

Private Key Unlock

Derived key decrypts your local RSA-4096 private key. It never leaves your device in plaintext.

→
03

Master Key Recovery

Private key unwraps the 256-bit master key via OAEP-SHA256. It exists only in memory, never on disk.

→
04

Chunk Encryption

Files split into 5 MB blocks. Each gets a unique random nonce and AES-256-GCM encryption with a 16-byte auth tag.

→
05

Ciphertext Sync

Only encrypted chunks, encrypted names, and encrypted metadata sync to your cloud. The provider sees nothing readable.

CRYPTOGRAPHIC ARCHITECTURE

Four independent layers
of protection.

If one layer were hypothetically compromised, the others remain intact. Defense in depth.

01

Key Derivation

Argon2id v1.3

Your password is never used as a key directly. Argon2id runs with 128 MB memory and 4 iterations — computationally expensive to deter brute-force attacks even with specialized hardware.

Memory131 072 KiB
Iterations4 passes

02

Master Key Wrapping

RSA-4096 OAEP

A random 256-bit master key encrypts your files. This key is wrapped with your RSA-4096 public key using OAEP-SHA256. Only your private key — which you alone hold — can unwrap it.

Key Size4096 bits
PaddingOAEP-SHA256
PurposeKey Wrapping
AccessPrivate Key Only
03

Content Encryption

AES-256-GCM

Each 5 MB chunk is encrypted with AES-256-GCM using a cryptographically random 12-byte nonce. A 16-byte authentication tag ensures any tampering — even a single bit flip — is detected immediately.

Nonce12 bytes (random)

Metadata Encryption

Zero Knowledge

VIDEO SECURITY

Large files, fully encrypted.
Chunk by chunk.

Videos are split into 5 MB segments. Each is independently encrypted with its own nonce — so even partial access reveals nothing.

01

5 MB Chunking

Videos split into 5 MB segments. Encryption and upload run in parallel for speed and resilience.

02

Per-Chunk Nonce

Every chunk gets a fresh random 12-byte nonce. Nonce reuse is architecturally prevented.

03

Authentication Tag

Each chunk carries a 16-byte GCM auth tag. Any modification triggers immediate failure.

04

Secure Reassembly

Chunks are verified and decrypted in order, only on your authorized device.
